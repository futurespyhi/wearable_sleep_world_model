## 3. 暂定主问题的最小定义

> 只使用出结果时刻之前的腕部运动和心率信息，持续时间建模能否改善未来 30 分钟的清醒总时长预测，且不以更高的未来短 Wake 事件漏报为代价？

30 分钟是供讨论的起始 horizon，需在查看可用覆盖与近邻协议后固定，不是已注册的实验参数。这里的“清醒负荷”仅指参考评分中的 Wake 总时长，不等同于临床 arousal、失眠程度或睡眠质量。

### 3.1 最小输入、输出与比较

| 项目 | 拟议定义与需要冻结的选择 |
|---|---|
| 输入 | 当前夜截至 `t0` 的腕部 HR/ACC 与有效性信息；历史长度和重采样方法在开发数据上确定 |
| 决策起点 | 固定周期、且仅依据当前及过去观测产生；不能通过未来 PSG 标签寻找“即将变化”的起点 |
| 主要目标 | 未来固定窗口内被参考标签标为 Wake 的总分钟数；不要求当前已经被判为睡眠 |
| 次要目标 | 有轨迹输出的模型比较未来分段概率、转变附近误差和短 Wake 片段的漏报；短片段阈值预先定义 |
| 直接比较 | 同信息 direct outcome regression、direct multi-horizon state prediction、latent transition、简单 Markov/HSMM；容量和训练选择尽量匹配 |
| 机制对照 | 对同一预测器比较有/无持续时间约束，或软先验/硬最小时长；参数只在开发集选择。跨模型比较本身不能隔离约束的作用 |
| 基线起点 | 当前状态只能由可用观测估计；不能给基线真实当前 PSG 状态而不给其他模型，也不能用真实未来状态初始化 rollout |
| 评价 | 主要报告总时长 MAE 与偏差；状态概率报告 Brier/NLL 和校准。每人等权，单独检查状态转变附近和数据质量较差时段 |
| 目标缺失 | 保留目标可评估覆盖和缺失原因；不把缺失参考标签填成睡眠或清醒，不用 outcome 挑选“好预测”的人 |
| 外部验证 | 不同设备/队列/参考标签分别报告；无法将它们的联合变化全部归因于设备差异 |

如果以每个 30 秒 epoch 的 Wake 概率求和，得到的是清醒总时长的**期望**。若要评价总时长的预测区间，还需要刻画 epoch 之间的依赖；不能把边际概率求和当成已经获得整段时长分布。

### 3.2 为什么值得问，以及什么会否定它

Gao 的 duration-aware 工作把最小持续时间作为应用约束，并评价 staging、dwell 分布和调度。该设定不能自动成为真实睡眠标签必须满足的生理规律。[Gao 原文 §3.1、§3.6、§4.6](https://arxiv.org/html/2610.33033v1)

SSF-SET 已经研究仅用过去 EEG 的未来阶段预测；Waqar 与 Ghani Khan 也已研究腕部多模态时序与睡眠模式。因此候选新意不是首次未来预测或首次使用腕部历史。本轮读取了 SSF-SET 摘要，以及后者 Methodology / Memory efficient models / Visualization；后者的 stage 输入可用性和自由 rollout 设置还需代码级核查。[SSF-SET](https://pubmed.ncbi.nlm.nih.gov/41662557/)、[Waqar et al., 2024](https://pmc.ncbi.nlm.nih.gov/articles/PMC11057653/)

要支持这个小切入点，至少需发现：在相同历史信息下，某种明确的状态或持续时间建模既改善主要结局，又没有通过抹掉短 Wake 标签换取平滑。短事件只在未来参考标签到达后评分，不要求模型预先确定地复现每个事件；事件阈值、匹配窗口及误报/漏报口径需先固定。以下任一结果都应改变判断：

- Direct outcome 或简单状态模型同样好，latent transition 没有增量。
- 轨迹看起来更稳定，但清醒总时长误差更大，或短 Wake 片段漏报增加。
- 增益只来自读取更多输入、不同样本筛选或不同标签，而不是拟议机制。
- 最接近已有研究已经回答同样的输入、目标、horizon 与评价问题；此时换问题或做有明确价值的复现。

若只是比较预测器而未验证有用的状态演化，应以 forecasting 研究如实报告；不为保持 world model 名称扩大声明。

## 4. 四条数据路线：按问题需求筛选

下表是官方说明层面的适配，不是已审核的最终 cohort。每条数据只承担它能支持的角色，不把不同参与者拼成同一个人，也不把不同来源的标签混成统一真值。

| 数据与固定版本 | 已确认的观测与标签 | 对应候选问题 | 访问及当前未决事项 |
|---|---|---|---|
| **DREAMT v2.2.0**，2026-06-02 | 100 人，睡眠门诊情境；Empatica E4 BVP、ACC、EDA、温度等，与专业 PSG 标签；有临床协变量 | G3：腕部多模态预测与转变/清醒片段评价的首选数据审核对象 | PhysioNet 注册并签指定 DUA 才可访问；本轮没有确认用户已具备权限。2.2.0 修复 ACC/PSG 对齐；`P` 在 100 Hz 目录被转成 `W`，需恢复参考有效区间。[D1] |
| **BIDSleep v1.0.1**，2026-09-25 | 47 人、253 夜、每人 3–7 夜；Apple Watch IHR/ACC，Dreem 2 自动及单专家复核标签 | G3：多夜、不同参考来源的外部验证或过去夜晚适应；不能支持 28 天个体历史实验 | Open Data Commons Attribution 1.0；公开。参考标签不是完整 PSG；没有多评分者裁决；IHR 约 0.2 Hz，不是 raw PPG。[D2] |
| **PMData**，2020 原始数据 | 16 人、5 个月；Fitbit Versa 2 活动、HR、sleep JSON / sleep score，与 PMSys wellness 自报 | G1：次夜设备时长/分数的可行性；G2：需先审查时区、每日输出时刻及可用特征 | 官方说明为 CC BY 4.0，并给 OSF 下载；本轮主站直开超时/OSF 拒绝抓取，字段来自官方搜索索引全文。尚未检查文件、缺失和实际可下载性；样本小。[D3] |
| **TILES-2018 Sleep Benchmark**，2025 作者稿 | 139 人、10 周、6,012 个记录；Fitbit Charge 2 夜间 HR、设备阶段、睡眠元数据及 baseline PSQI | G1：较长序列与不同人群的设备结局外测；不是逐 epoch 独立 PSG 验证 | 官方门户需登录；原始访问资格/包版本待核。缺少逐夜主观质量标签；不能把 baseline PSQI 当成每晚 quality。日/夜班字段也不是已验证的随机行动日志。[D4] |

### 4.1 数据适配中必须保留的区别

- G3 需要同步的腕部观测和参考标签；目前 DREAMT 与 BIDSleep 的官方说明满足进一步检查的理由，但人数不能代替有效窗口/短事件数量。
- G1 需要多周重复夜晚；PMData/TILES 更符合时间跨度。这里预测的设备结局不能自动解释为真正的生理质量；同品牌设备评分间也应检查算法版本。
- DREAMT 的预处理版本、BIDSleep 的参考来源与跨数据集共同 HR/ACC 接口，都会影响实验可比性；具体读取实现尚未审查。
- 若数据没有到达/同步时间，离线 replay 最多验证明确假设下的可用性；不能声称已经完成端到端真实在线验证。
- 所查字段尚未提供本轮拟议的随机提醒或温控日志。行动分支暂保留为有条件方向，不能从运动记录、消费设备评分或班次类别推造 action。

## 5. 数据审核的下一步，与停止条件

以下属于本轮研究产物导出的下一步，尚未执行原始数据处理或模型实验。

1. 先确认选 G3 还是 G1；组会暂以 G3 为主问题、G1 为备选。
2. 对首选数据检查许可、已有访问和目录/标签 schema；确认数据版本及参考标签有效范围。
3. 统计可用的人、夜、history/target 覆盖和目标变化，检查时间戳、采样率、重复记录及缺失。所有计数在数据审核后才报告。
4. 固定 task card：输入、cutoff、label window、split、主要指标、强基线和允许的适应信息。
5. 在现有文献与公开实现中继续查找等价任务；数据具备和问题新颖是两个独立条件。

如果没有足够事件或覆盖，缩小可证实的目标/结论或调整数据路线。如果数据只能支持同期识别，就按识别来表述。如果没有同信息基线增益，不升级到更复杂模型或干预声明。
